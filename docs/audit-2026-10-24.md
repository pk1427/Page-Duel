## C. Findings, grouped by severity: Critical, High, Medium, Low. Each with file path, what is wrong, and why it matters

### Critical

1. `supabase/migrations/20261016000000_admin_auth_and_rls.sql:78-124` grants authenticated admins broad direct `UPDATE` on `books` and `book_versions`. The lifecycle trigger in `20261016060000_fix_secure_publishing_service_role_detection.sql:21-31` protects only four version fields; it does not prevent direct mutation of `content_json`, nor direct publication-state changes on `books`. This conflicts with the claimed Edge-Function-only publish boundary and permits an admin JWT to alter content outside validation/audit paths.
2. `supabase/functions/book-publish/index.ts:8-9` uses `Access-Control-Allow-Origin: *` while accepting bearer-authenticated publishing requests. The function does not use cookies, but this is unnecessarily broad for a privileged browser endpoint and has no per-environment allowlist.
3. `apps/game/src/session-store.tsx:160-166` discards Supabase error `code`, status and details; known credential failures are replaced with a generic message at lines 23-52. The current top blocker cannot be diagnosed from the UI safely.
4. `supabase/tests/admin_custom_access_token_hook.test.sql:26-28` asserts an admin, after setting an `admin=true` claim, sees zero `admin_users` rows. The RLS policy permits the auth-hook role only, while authenticated has no SELECT grant; the assertion is not a valid authorization test and conflicts with the admin audit grant rollout. It should assert an authenticated SELECT is denied (or reset to the player JWT before asserting no rows), not rely on `count(*) = 0`.

### High

1. `apps/game/src/game-store.tsx:69-73` falls back to local books after a configured hosted catalog request fails, but `apps/game/src/catalog.ts:195-201` refuses local content whenever Supabase is configured. Books can render but cannot be selected/played after a catalog outage.
2. `apps/game/src/app/books.tsx:22-76` does not render `catalogLoading` or `catalogError`; it silently shows a fallback shelf. This masks the above production failure and can make catalog/RLS trouble look like an ordinary book-selection failure.
3. `tools/book-prep/publish.py:77-85, 275-280` implements `--force` with storage upsert. It is destructive overwrite behavior, not merely retry behavior; the script has no object hash comparison or confirmation beyond the flag. The Edge Function is safer (conflict rather than overwrite).
4. `apps/game/src/app/reset-password.tsx:49-63` treats a valid existing session without a recovery hash/token as invalid. Browser refresh after Supabase consumes/cleans the URL fragment can falsely reject a usable recovery session.
5. `docs/product-architecture.md:16,35` omits `/history` from protected routes and says history/persistence have not shipped; code protects history in `auth-routing.ts:4-11`, renders it in nav, and saves matches in `result.tsx:29-63`.

### Medium

1. `apps/game/staging.sh:48` and `apps/admin/staging.sh:48` print the configured Supabase URL. It is not a secret, but it contradicts the requested diagnostics posture and can lead operators to paste environment output unnecessarily.
2. `supabase/migrations/20261015010000_catalog_seed.sql:14-20` is intentionally idempotent but uses `ON CONFLICT DO UPDATE`; this is non-append-only seed behavior and may overwrite catalog metadata on reapplication.
3. `supabase/migrations/20261016000000_admin_auth_and_rls.sql:87-92,118-124` permits admin DELETE of books and versions despite comments preferring archival. This can cascade-delete versions and null history FK references.
4. `apps/game/src/content-assets.ts:3,15-19` falls back to `http://localhost:8000` even in a configured release if asset variables are absent. This will fail on Android/web devices outside the developer machine.
5. `apps/game/src/session-store.tsx:62-67` marks a session with no email as signed-in. Supabase email/password users normally have an email, but this state is inconsistent and could bypass a UI assumption.

### Low

1. Dependency versions are consistent between game/admin (Expo `~57.0.26`, React `19.2.3`, React Native `0.86.3`), but `typescript` is `~6.0.3` in apps and `^5.6.0` in packages. No Drizzle/Neon references were found. Compatibility with Expo SDK 57 is not verified because Expo commands did not complete.
2. `apps/game/src/app/_layout.tsx:13-21` correctly prevents simultaneous top/bottom nav and hides nav only for `/game`; the architecture’s results actions are stale because `result.tsx:158-160` now includes History.
3. `docs/asset-hosting.md:149-153` is internally contradictory: it declares a `public=true` bucket, then says public reads are RLS-scoped and only authenticated users can read. Public Storage URLs bypass the stated authenticated-read claim; intended policy is the `books/` prefix in `20261015020000_storage_bucket.sql:29-51` for API role reads.

## D. Sign-in failure diagnosis: ranked likely causes + what evidence to capture

1. **Wrong or stale hosted URL/anon key/environment selection.** Game uses only `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` (`apps/game/src/supabase.ts:6-10`); game staging loads `.env.staging.local`, while admin staging loads `.env.local`. Capture DevTools Network request URL, HTTP status, response `code`/`message`, and the *variable names and URL host only* (never keys).
2. **User/confirmation/password state.** `signInWithPassword` is called at `session-store.tsx:160-163`; confirmation errors are reduced to friendly text. Capture the `/auth/v1/token?grant_type=password` response code/message and whether the account is confirmed in the Supabase Auth dashboard.
3. **Redirect allowlist/recovery callback mismatch.** Reset requests use `window.location.origin + /reset-password` (`forgot-password.tsx:18-25`). Capture the exact origin and the Auth redirect URL allowlist entry; required entries are local web origin + `/reset-password`, staging web origin + `/reset-password`, and production web origin + `/reset-password` (plus native deep-link equivalents if native recovery is supported).
4. **Network/CORS/DNS/TLS issue.** Current mapper groups these as “Unable to connect” (`session-store.tsx:48-49`). Capture browser console error plus Network timing, request URL host, status, and response headers—redacting Authorization/key values.
5. **Session storage or route transition.** Web uses `localStorage`; native uses SecureStore with memory fallback (`supabase.ts:18-58`), and sign-in redirects on state changes (`sign-in.tsx:27-48`). Capture the auth-state event name, `getSession` result shape (presence only), current pathname, and localStorage key names only.

Recommended safe diagnostic change before testing: log/display a correlation-safe `{code, status, message}` for the auth error in development, preserving the user-friendly copy and never logging credential input, token, key, or full response body. It is not present today.

## F. Things that should be rewritten or refactored before upgrading (with reasoning)

1. Centralize catalog failure states: distinguish loading, failed hosted catalog, and deliberate offline fallback; never display unselectable local books when Supabase is configured.
2. Make publish lifecycle genuinely server-owned: remove client-admin direct mutation grants/policies for lifecycle/content hashes, expose narrowly scoped server RPC/Edge operations, and ensure every privileged lifecycle action audits.
3. Replace generic auth error mapping with safe structured diagnostics and add tests for `code`, confirmation, network, persistence, and redirect failures.
4. Split `publish.py` archival/bulk tooling from the Edge Function contract; make idempotency hash-based and prohibit overwrite by default, including `--force` unless an explicit destructive workflow is authorized.
5. Bring docs under a single deployment contract: public-bucket semantics, history feature, actual routes, required redirects, and production/staging configuration must agree.
